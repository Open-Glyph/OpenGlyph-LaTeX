# 从下载到写论文

## 1. 只用已有字：不必安装造字环境

下载 Release 中的 `openglyph-overleaf-v0.1.0.zip`。Overleaf 选择「新建项目 → 上传项目」，上传 ZIP，然后在菜单里把编译器改为 XeLaTeX，主文件设为 `main.tex`。

本地写作也一样：将 `openglyph.sty` 与 `ebag/` 保持相邻，放在论文文件夹，用 XeLaTeX 或 `tectonic main.tex` 编译。

如果要放入已有论文，只复制 `openglyph.sty` 和 `ebag/`，在导言区加入：

```tex
\usepackage{openglyph}
\OpenGlyphLoad{ebag}
```

正常汉字照常输入，只有特殊字用 `\ebag{s030-067}`。不要手动复制一个 PUA 地址然后指望所有字体都认识它。

## 2. 怎么知道字的编号

解压后打开 `字形索引.html`。它直接使用本地字体显示字形，不需要登录或联网。输入 `s030-067` 可定位；也可以按 `u81e3` 之类的部件名称筛选。输入普通汉字会被用于部件名称检索，不代表候选字就是这个汉字。

点选合适字形后复制命令。候选形应与文献原形逐笔核对，不能仅凭读音、构形或相似度选第一项。

## 3. 造新字只需准备一个 JSON

参照 `examples/newforms.json`。`base` 选最接近的已存在形；`edits` 是本字上的局部操作。

| 操作 | 示例字段 | 作用 |
|---|---|---|
| replace | node, glyph | 替换一个部件实例 |
| insert | parent, id, glyph, box | 增加部件或 dot/bar/slash/loop 基元 |
| drop | node | 删除指定笔画记录或部件 |
| place | node, box | 调整部件的位置和比例 |
| move | node, delta | 局部平移 |
| group | parent, id, nodes | 把相邻记录归成模块，再整体编辑 |

用 `python scripts/openglyph.py inspect ebag:s030-067 --node r4` 查看当前层编号。`r4/r0/r2` 是该版本中的出现路径，不能硬套到别的字。`box` 是父部件的 200 单位字格，不是扫描图坐标。

构字程序的节点层级不必等同于语义 IDS：一组口形可能是四条散笔，而不是一个单独命名的口部件。`group` 可将这样的散笔归成一个可操作模块。

编译命令：

```sh
python scripts/openglyph.py build examples/newforms.json -o myglyphs
```

输出 `myglyphs/` 包含真实 OTF、`catalog.tex`、`manifest.json`、稳定码位分配和可重放程序。导言区加 `\OpenGlyphLoad{myglyphs}`，正文用 `\gwglyph{my:n2}`。

## 4. 修改已有项目时不要乱换地址

```sh
python scripts/openglyph.py build my-project-v2.json -o myglyphs-v2 \
  --allocation myglyphs/allocation.json
```

已有 ID 继续使用原来的字体局部地址。删掉的 ID 保留退役记录，避免旧论文文字指向新字。实际字体与内容哈希仍会因字形修改而变化；提交论文时务必同时保存正确版本的字体和映射。

不要在同一文档加载两个使用同一个 namespace 的不同版本。宏包会拒绝冲突，不猜测你想用哪一个。

## 5. 投稿和与合作者共享

- 给期刊 PDF：字体已经嵌入，不要求审稿人安装字体。
- 给合作者源码：一起发送 `.tex`、`openglyph.sty`、所用字体目录以及许可说明。
- 给 Word 用户：可以安装 OTF 并选择相应字体；仅复制 PUA 而没有字体，可能显示方框或另一个字。
- 标题与 PDF 书签：纸面显示字形；书签用 `[ebag:编号]` 之类的文字回退，避免把不可通用的 PUA 塞进书签。
- 不必开启 shell-escape；不要为排印同一篇论文重复调用付费模型。

## 6. 验证与已知限制

`python scripts/verify_bundle.py ebag` 检查全部码位、字形轮廓与 LaTeX 映射。它是工程完整性检查，不是学术验收。

首次发布保留了原始来源程序和历史组件版本，没有去掉饰笔、把繁简字归一或强行替换为常用字。视觉上每一个具体形是否适合你的文献，仍由研究者确认。

使用者无须逐笔编程。当前也没有承诺从任意图片自动生成完全相同的字；没有部件可用时，需要补充部件或进一步编辑，而不是冒充识别成功。

首版为横排论文与局部字形混排提供支持。整篇古籍竖排、分页校勘、多层注释不是本宏包自带的排版系统。
